# 系统课程工作流

## 固定位置

使用以下 Vault 相对路径：

- 课前须知：`02_AI学习/课前须知.md`
- 知识库：`02_AI学习/知识库/`
- 个人笔记：`01_我的笔记与代码/`

**读取和写入 Vault 中的 Markdown、TXT、代码及其他文本文件时，始终明确使用 UTF-8 编码。每次调用 Windows PowerShell 工具时，先执行 `[Console]::InputEncoding = [System.Text.UTF8Encoding]::new($false); [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false); $OutputEncoding = [Console]::OutputEncoding`，并为 `Get-Content` 等文件读取命令显式指定 `-Encoding UTF8`。调用 Python 处理文本时显式使用 `encoding="utf-8"`。如果终端显示乱码，不要把乱码内容当成原文，立即改用显式 UTF-8 方式重新读取。**

## 一、确定本次教学章节

1. 读取 `02_AI学习/课前须知.md`，遵守其中的角色定位、学生基础、技术环境和教学内容自检要求。
2. 根据用户提出的学习主题，确定一个能够在当前连续会话中完成的教学章节。
3. 如果主题范围过大，主动将其拆分为具有依赖顺序的章节，并简要说明整体结构和本次要完成的章节。
4. 承担课程结构、知识顺序和内容覆盖的设计责任，不要求用户代替教师设计课程。
5. 检查知识库中是否已有相同或高度重合的章节。发现重复时，先说明情况，再确认继续、补充、重学或创建新版本。
6. 读取与本章直接相关的 `教学反馈.md`。只有需要核对具体定义、代码、推导或历史约定时，才读取以前的 `完整教学.md`。
7. 用简短内容说明本章要解决的问题和大致范围，然后开始教学。

## 二、完成本章教学

1. 在同一个对话窗口中完成本章。
2. 按照课前须知中的教学内容自检问题组织课程，保持系统性、逻辑连贯性和学生可读性。
3. 将本章拆分为若干逻辑完整、篇幅适中的教学小节，一次只讲一个小节。不要在一条回复中把整章内容全部丢给用户，也不要同时引入过多新概念。
4. 每个小节应当把当前问题讲清楚，但不要为了缩短单次回复而切断必要的定义、推导、示例或代码解释。讲完当前小节后停下来，让用户决定“懂了”“没懂”或提出问题；只有用户确认可以继续时，才进入下一小节。
5. 保持明确的课程主线，不因临时答疑遗忘原定章节结构。
6. 用户表示“懂了”时继续下一部分，但不要据此推断当前讲法一定轻松或有效。
7. 用户表示“没懂”时停留在当前逻辑节点，判断缺失的是前置概念、概念关系、推理步骤、示例映射还是代码理解，再重新组织解释。不要只更换近义词重复原文，也不要在卡点解决前继续堆积后续内容。
8. 用户提出具体问题时，先完整处理问题，再明确回到课程主线的哪个位置。
9. 教学过程中不创建或更新知识库文件。将当前对话作为本章教学过程的临时载体。

## 三、确认章节结束

仅在以下条件同时满足时结束教学：

1. 本章预定的核心内容已经全部讲授；
2. 必要的前置概念已经得到解释；
3. 关键定义、原理、推导、示例和代码之间没有尚未处理的逻辑断点；
4. 教学过程中产生的重要疑问已经处理；
5. 用户明确确认本章可以结束。

如果仍有关键内容没有讲清楚，继续教学，不要提前进入文件保存阶段。

## 四、保存完整教学

用户确认本章结束后，创建本章目录，并根据本章完整对话生成 `完整教学.md`。

以实际聊天中的教学内容为原稿，按照真实授课顺序保留：

- AI 给出的全部实质性讲解；
- 概念、定义、推导、例子和反例；
- 完整代码及其解释；
- 用户提出的实质性问题；
- 因用户没有理解而产生的重新解释；
- 课程中最终确认的修正内容。

只对原始内容进行必要整理：

- 删除寒暄、“懂了”“继续”等进度控制内容；
- 删除工具调用、文件操作和其他与教学无关的内容；
- 修正错别字、Markdown 排版和明显口误；
- 统一前后不一致的术语和变量名称；
- 删除完全相同、没有新增解释价值的机械重复；
- 对已经纠正的错误采用最终正确版本。

除以上必要整理外，其余教学内容正常保留。不要重新压缩、概括或改写成另一篇文章。

不得把 `完整教学.md` 转换成摘要、提纲、知识点清单或复习笔记；不得因为文件较长而省略已经讲过的推导、例子、代码、问题或重新解释；不得用一句总结替代原对话中的完整教学过程；不得使用“前文已经讨论”“如聊天中所述”等依赖原对话才能理解的表达。

写完后对照本章对话检查一次，确保没有误删具有教学价值的内容。

## 五、共同完成教学反馈

完整教学保存后，与用户讨论本章的实际学习体验。重点讨论：

- 哪些部分理解得比较顺畅；
- 哪些部分虽然最终听懂，但理解过程很吃力；
- 哪里出现了过大的逻辑跨度；
- 哪些术语、规则或边界情况出现得过于集中；
- 哪些地方只是能够跟随解释，还没有形成稳定直觉；
- 未来讲授相关内容时应当怎样调整。

根据讨论结果起草 `教学反馈.md`，并交给用户确认。只记录用户明确表达的实际体验，以及双方确认的后续教学调整。

不要由 AI 单方面评价自己的教学效果，不要把未经用户确认的推测写成稳定的学习者特征。如果用户暂时不想完成反馈，保留完整教学文件并说明反馈尚未完成，不要自行补写。

## 六、组织知识库目录

对于属于大型课程的章节，使用：

```text
02_AI学习/知识库/<课程名称>/<章节名称>/
├─ 完整教学.md
└─ 教学反馈.md
```

例如：

```text
02_AI学习/知识库/现代C++/对象生命周期/
├─ 完整教学.md
└─ 教学反馈.md
```

对于能够独立完成的小主题，使用：

```text
02_AI学习/知识库/<主题名称>/
├─ 完整教学.md
└─ 教学反馈.md
```

使用具体、稳定且不重名的名称。避免使用“概述”“第一课”“新知识”“临时课程”等脱离目录后无法判断内容的名称。

仅在用户确认章节结束后创建本章目录和教学文件。将本 Skill 的默认写入范围限制在 `02_AI学习/知识库/`；如需修改个人笔记或课前须知，先取得用户明确许可。
